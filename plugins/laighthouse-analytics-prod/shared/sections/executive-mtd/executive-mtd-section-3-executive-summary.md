# Executive-MTD Section 3: Executive Summary

**report_type:** `executive-mtd` (항상 포함) — naver 기반 default generator 브랜드 전용
(남양유업 등).

mtd(MK)의 `mtd-section-3-executive-summary.md`와 HTML 골격(카드 + 불릿 리스트)은 같지만,
**내용의 목적과 대상 독자가 다르다**. mtd(MK)의 Executive Summary는 담당 실무자가 "지금 무엇을
해야 하는지"를 판단하도록 페이싱·소진 속도 위주로 쓰지만, executive-mtd의 Executive Summary는
**임원이 딥다이브 없이도 "무엇을 결정해야 하는지"를 파악하도록** 쓴다. 참고 스크린샷
(1번 스크린샷)은 흰 배경의 평범한 불릿 카드 3개로 구성되어 있다 — **스크린샷 하단에 있던
색깔 입힌 "승인 필요" 박스는 이 섹션에 포함하지 않는다** (그런 승인/버튼 UI 컴포넌트를 만들지
않는다). 의사결정이 필요하다는 내용 자체는 평범한 불릿 문장 안에 자연스럽게 녹여서 쓴다.

## 텍스트 생성: 아래 사항을 모두 준수하여, AI가 직접 작성 (`df_dify` MCP 호출 안 함)

⚠️ **`df_dify` MCP 서버는 현재 호출하지 않는다** (연결 불안정으로 타임아웃 시 빈 응답이 돌아옴).

```
작성 순서:
1. 수치 데이터 수집 — 별도 재호출 없이 이미 다른 섹션에서 받은 응답을 재사용한다:
   - executive-mtd-section-1(목표 달성 현황)의 get_target_progress_v2 응답
   - executive-mtd-section-2(월별 광고 성과 차트)의 get_naver_monthly_ad_performance 응답
   - executive-mtd-section-4(주요 카테고리별 월간 매출액 증감)가 이미 가공한 카테고리별 MoM 비교 데이터
   - executive-mtd-section-5(매체별 성과 비교)가 이미 가공한 채널별 ROAS MoM 비교 데이터
2. dify 호출 없이, 1의 수치 데이터를 근거로 AI가 executive_summary 텍스트를 직접 작성한다.
   각 문장은 "카테고리 또는 채널 단위로 데이터상 확인되는 특이사항"이어야 하며, 특이사항이 없는
   카테고리/채널은 억지로 언급하지 않는다 (특이사항이 있는 것만 고른다).

<작성 원칙 — 반드시 지킬 것>:
1. 각 불릿은 "무슨 일이 있었는지(수치) + 왜 임원이 신경 써야 하는지(시사점)"의 두 부분으로 구성한다. 단순히 수치를 나열하거나(mtd처럼 "~% 소진되었습니다") truism은 제외한다. (고효율 채널 및 카테고리를 중심으로 예산 확대를 검토합니다.)
2. 아래 세 가지 유형의 특이사항을 우선적으로 찾아 기술한다 (해당 사항이 있을 때만; 모든 유형을
   억지로 채우지 않는다):
   a) **예산 재검토가 필요한 성장 신호** — 특정 카테고리가 연속 성장하며 예산 확대/재배분을 검토할 만한 근거가 되는 경우. truism이 되지 않도록 근거 데이터를 반드시 함께 기술한다. (예: "단백질보충제가 전월 대비 +61.5% 성장하며 4개월 연속 확대. 클릭 단가는 -37% 하락해 비용 효율도 함께 개선.")
   b) **원인 확인이 필요한 하락 신호** — 특정 카테고리/채널의 매출·ROAS가 여러 달 연속 하락하거나 다른 카테고리/채널 대비 뚜렷하게 나쁜 경우 (예: "커피 카테고리는 3개월 연속 매출 하락(전월 대비 -13.5%). 광고 직접 매출도 동반 감소해 상품팀과 마케팅팀의 실무자와 함께 점검이 필요한 상황.")
   c) **효율 변화가 뚜렷한 채널** — 여전히 고효율이지만 추세가 꺾이고 있는 채널, 또는 반대로 눈에 띄게 개선된 채널 (예: "네이버 GFA 애드부스트는 여전히 고효율 채널(ROAS 823%)이나 전월 대비 -18%p 하락 중.")
   d) **프로모션 효과 예상** - 'list_promotions'의 정보를 참고하여, MTD 기간에 진행된 프로모션 정보를 기술한다. 프로모션이 성과 개선에 도움이 되었는지를 분석한다. 만약 'list_promotions'에서 관련된 정보를 찾을 수 없다면 본 d) 불릿은 생략한다.
3. 문장 수는 3~5개로 제한한다 — 임원 보고이므로 다다익선이 아니라 "정말 중요한 것만" 고른다.
4. 새로운 수치를 지어내지 않는다 — 근거가 없는 원인 추정(예: "경쟁사 프로모션 때문일 것")은 쓰지 않는다. 대신 "확인이 필요하다", "점검이 필요하다"처럼 사실과 그에 대한 다음 행동 제안까지만 쓴다.
```

## 응답 데이터 구조

```json
{
  "executive_summary": "단백질보충제가 전월 대비 +61.5% 성장하며 4개월 연속 확대. 클릭 단가는 -37% 하락해 비용 효율도 함께 개선.\n커피 카테고리는 3개월 연속 매출 하락 (전월 대비 -13.5%). 광고 직접 매출도 동반 감소해 상품·마케팅 합동 점검이 필요한 상황.\n네이버 GFA 애드부스트는 여전히 고효율 채널(ROAS 823%)이나 전월 대비 -18%p 하락 중."
}
```

- `executive_summary` 값이 문자열이면 그대로 `<p>`로 렌더링
- 줄바꿈(`\n`) 기준으로 분리하여 각 줄을 `<li>`로 렌더링 (한 줄 = 한 불릿 = 한 특이사항)
