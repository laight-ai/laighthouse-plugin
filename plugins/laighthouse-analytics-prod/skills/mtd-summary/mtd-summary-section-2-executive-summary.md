# Breezm Executive MTD Section 2: Executive Summary

**report_type:** `executive-mtd` (항상 포함) — **브리즘(airbridge 기반, type-b) 전용**.

브리즘의 Executive Summary는 **임원이 딥다이브 없이도 "현재 전체적인 성과"를 파악하고, 그 주된 원인이 무엇인지를 알 수 있도록**
쓴다. 단순 수치 나열(예: "~% 소진되었습니다")이 아니라, 전체 매출·채널(Google/Meta/Naver Ads) 단위·
매출 구조(오거닉 vs 광고) 단위로 "성과가 좋은지/보통인지/나쁜지 + 왜 그런 성과가 발생했는지"를 담는다.
**색깔을 입힌 "승인 필요" 강조 박스(전체 배경색, 버튼, 배지 등)는 만들지 않는다** — 흰 배경의
평범한 불릿 카드로만 구성한다. 의사결정이 필요하다는 내용 자체는 평범한 불릿 문장 안에
자연스럽게 녹여서 쓴다.

---

## MCP 도구 호출: `list_promotions` × 1

```json
{ "brand_name": "브리즘", "start_date": "월초 30일 전 YYYY-MM-DD", "end_date": "target_date" }
```

- 이 섹션에서 **유일하게 새로 호출하는 도구**다 (나머지 데이터는 아래처럼 다른 섹션 응답을
  재사용한다). `start_date`를 당월 1일이 아니라 **그보다 30일 더 앞선 날짜**로 잡는다 —
  분석 기간(당월 1일~기준일)과 직접 겹치지 않아도, 그 직전에 끝난 프로모션/캠페인이 이번 달
  초반 성과에 이월 영향을 줄 수 있기 때문이다 (아래 「이월 효과」 규칙 참고).
- 응답에 프로모션이 전혀 없으면(겹치는 것도, 직전에 끝난 것도 없음), 아래 (e) 유형의 불릿은
  만들지 않는다 — 억지로 "프로모션이 없었습니다" 같은 문장을 추가하지 않는다.

## 텍스트 생성: 아래 사항을 모두 준수하여, AI가 직접 작성 (`df_dify` MCP 호출 안 함)

⚠️ **`df_dify` MCP 서버는 호출하지 않는다** (브리즘은 애초에 이 서버를 쓰지 않는다 — naver 기반
브랜드 전용 도구다). 아래 「MCP 도구 호출」의 `list_promotions` 1회를 제외하면 이 섹션은 새로운
MCP 호출 없이 다른 섹션 응답만 재사용한다.

```
작성 순서:
1. 수치 데이터 수집 — 별도 재호출 없이 이미 다른 섹션에서 받은 응답을 재사용한다:
   - mtd-summary-section-1(목표 달성 현황)의 get_target_progress_v2 응답
     (google/meta/naver 3회) — 목표/소진율/매출 달성률/ROAS. 브리즘은 현재 media_mix 예산
     목표가 없어(세 매체 모두 no-budget) 이 값들이 전부 N/A인 것이 기본 상태다. **N/A인 목표
     수치를 근거로 삼은 문장은 쓰지 않는다** — 그 경우 목표 달성 관련 언급 없이 실적(소진액/
     기간 매출/실제 ROAS) 중심으로만 쓴다.
   - mtd-summary-section-3(월별 광고 성과 차트)의 get_ad_performance_monthly_table
     응답(google/meta/naver + airbridge, 최근 6개월) — 월별 광고비/매출/ROAS 추이.
   - mtd-summary-section-4(매출 추이)가 이미 가공한 **전체 매출 vs 광고 매출** 추이
     데이터 — 오거닉 매출(전체 매출 − 광고 매출)과 광고 매출의 비중이 최근 어떻게 변했는지
     비교한다.
   - mtd-summary-section-5(Channel별 성과 비교)가 이미 가공한 **채널별(Google Ads/
     Meta Ads/Naver Ads) 매출·ROAS 변화율(전월 대비)** 비교 데이터.
   - 위 「MCP 도구 호출」에서 새로 받은 `list_promotions` 응답 — 당월 MTD 기간과 겹치는
     프로모션/이벤트뿐 아니라, 그 직전 30일 이내에 종료되어 이월 효과를 남길 수 있는
     프로모션/이벤트명·기간도 포함한다.
2. dify 호출 없이, 1의 수치 데이터를 근거로 AI가 executive_summary 텍스트를 직접 작성한다.
   각 문장은 "채널 또는 매출 구조 단위로 데이터상 확인되는 특이사항"이어야 하며, 특이사항이
   없는 채널은 억지로 언급하지 않는다 (특이사항이 있는 것만 고른다).

<작성 원칙 — 반드시 지킬 것>:
1. 분석 내용은 큰 틀에서 다음과 같은 흐름으로 구성된다.
	a) mtd 기간의 성과에 대한 판단(좋았음, 보통 수준, 나빴음)
	b) 판단에 대한 근거(가장 대표적인 지표 하나만 언급)
	c) 성과가 좋거나 나빴던 가장 큰 원인에 대한 가설 및 그 근거 데이터 (가장 대표적인 데이터 하나만 언급)
	d) 좋았던 요소를 계속 이어가거나, 나빴던 요소를 예방 또는 차단하기 위한 액션 아이템 (예: 향후 운영에 참고해야함. 또는 구체적인 개선안에 대해 실무자와 논의가 필요함)
2. 단순히 수치를 나열하거나 truism은 제외한다. 주장이나 분석에 대해서는 반드시 가장 핵심적인 데이터 하나를 함께 제시해야 한다.)
3. 총 4개의 불렛 포인트에서는 다음과 같은 사항을 기술한다. 
	a) 전체 매출 성과 리뷰: mtd의 전체 매출을 전월과 비교하여 성과의 좋음/보통/나쁨을 <두괄식으로> 명시한다. 그리고 핵심 근거 데이터를 명시한다. (광고 매출의 등락도 포함하여 설명한다.) 
	b) 광고 성과 리뷰: 전월 동기와 비교한 매출 및 ROAS를 기준으로 광고 성과의 좋음/보통/나쁨을 <두괄식으로> 명시한다. 그리고 핵심 근거 데이터를 명시한다. 
	c) 광고 매체에서 확인된 특이사항. b)의 성과 판단을 뒷받침하는 핵심 지표를 하나만 설명. 예를 들어, ROAS가 개선되었다면 어떤 매체에서 크게 개선되었는지? 혹은 ROAS가 악화되었다면 어떤 매체에서 악화되었는지를 기술한다. 
	d) c)에서 설명한 현상의 원인이 될 수 있는 가설 제시. 가설을 검증하기 위한 거시적 차원에서의 검토 사항이나 액션 아이템 설명. 만약 특정 매체에서 성과가 개선되었다면 그 원인이 무엇인지에 대해 주어진 데이터와 맥락 정보에 근거하여 가설을 세운다. (예: 프로모션, 새로 추가된 캠페인이나 소재 덕분에 성과가 개선된 것으로 예상됨. 차기 프로모션 기획에 참고하거나, 유사한 소재를 기획하도록 실무자와 논의 필요)
4. 각 불렛포인트의 문장 수는 3개 이하로 제한한다 — 임원 보고이므로 다다익선이 아니라 "정말 중요한 것만" 고른다.
5. 새로운 수치를 지어내지 않는다 — 근거가 없는 원인 추정(예: "경쟁사 프로모션 때문일 것")은
   쓰지 않는다. 대신 "확인이 필요하다", "점검이 필요하다"처럼 사실과 그에 대한 다음 행동
   제안까지만 쓴다.
6. **Airbridge, GA4처럼 데이터를 수집·측정하는 특정 솔루션/도구의 이름을 본문에 언급하지
   않는다** — 임원에게는 지나치게 미시적인 정보다. 매출 귀속(어트리뷰션) 방식 변화 가능성을
   원인 가설로 들어야 할 때도 솔루션명 없이 일반적인 표현으로 쓴다. (예: "Airbridge의
   매출 귀속 방식이 바뀐 것인지 확인이 필요합니다" → "매출 산정 방식에 특이사항은 없었는지
   검토가 필요합니다")
```

## 응답 데이터 구조

```json
{
  "executive_summary": "Google Ads 매출이 전월 대비 +22.4% 성장, ROAS도 240.3%p 개선되며 예산 확대를 검토할 시점.\nMeta Ads 매출이 전월 대비 -19.8% 감소하고 ROAS도 -14.5%p 하락해 소재·타겟팅 점검이 필요한 상황.\n6월 30일까지 진행되었던 브랜딩 캠페인(유튜브 콜라보)이 7월 초 매출에 이월 영향을 줬을 가능성이 있어, 7월 첫 주 매출 추이를 함께 살펴볼 필요가 있습니다."
}
```

- `executive_summary` 값이 문자열이면 그대로 `<p>`로 렌더링
- 줄바꿈(`\n`) 기준으로 분리하여 각 줄을 `<li>`로 렌더링 (한 줄 = 한 불릿 = 한 특이사항)

## 렌더링 규칙
- 각 불릿을 감싸는 카드는 흰 배경, 옅은 회색 테두리(`#e2e8f0`)의 **평범한 카드**로만 렌더링한다
  — 색깔을 입힌 강조 배경, 버튼, 배지 등이 있는 "승인 필요" 박스는 만들지 않는다.
- 앞머리 점(●) 색상(`{DOT_COLOR}`)은 내용의 성격에 따라 구분한다: 성장/개선 신호는
  `#16a34a`(초록), 하락/점검 필요 신호는 `#dc2626`(빨강), 중립적 관찰(예: 오거닉/광고 비중 변화
  안내, 뚜렷한 효과가 확인되지 않은 프로모션, "가능성이 있다" 수준의 이월 효과 추정)은
  `#78716c`(회색-갈색). 프로모션 불릿은 효과가 뚜렷이 긍정적이면 초록, 부정적(예: 프로모션
  기간/직후에 매출이 하락)이면 빨강을 쓴다.
- 강조 수치는 `<strong>` 태그 사용.
- 불릿 개수가 5개를 초과하면 상위 5개(가장 임팩트가 큰 것)만 남긴다.
