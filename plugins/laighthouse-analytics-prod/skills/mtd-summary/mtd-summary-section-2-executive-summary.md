# Breezm Executive MTD Section 2: Executive Summary

**report_type:** `mtd-summary` — **브리즘(airbridge 기반) 전용** (항상 포함). **임원이 딥다이브
없이도 "무엇을 결정해야 하는지"를 파악하도록** 쓴다 — 단순 수치 나열이 아니라 채널/매출 구조
단위로 "무슨 일이 있었는지 + 왜 임원이 신경 써야 하는지"를 담는다.

> ℹ️ 불릿 카드 HTML(흰 배경 카드 + 색상 점 ●) 렌더링은 빌더가 한다 — 모델은 아래 규칙으로
> 텍스트만 작성해 빌더 입력 JSON의 `s2.bullets`(배열)에 넣는다. 각 항목은
> `{"text": "...", "color": "green"|"red"|"neutral"}` — 강조 수치에 `<strong>`을 써도 된다.
> 색깔 배경의 "승인 필요" 강조 박스·버튼·배지는 만들지 않는다(빌더 카드가 유일한 형식).

## MCP 도구 호출: `list_promotions` × 1 (이 섹션의 유일한 신규 호출)

```json
{ "brand_name": "breezm", "start_date": "당월 1일보다 30일 앞선 YYYY-MM-DD", "end_date": "target_date" }
```

- `start_date`를 당월 1일이 아니라 **30일 더 앞선 날짜**로 잡는다 — 직전에 끝난 프로모션이
  이번 달 초반 성과에 이월 영향을 줄 수 있기 때문 (아래 (e) 유형).
- 프로모션이 전혀 없으면 (e) 유형 불릿을 만들지 않는다 — "프로모션이 없었습니다"류 문장 금지.

## 텍스트 생성: AI가 직접 작성 (`df_dify` MCP 호출 안 함)

⚠️ **`df_dify` MCP 서버는 호출하지 않는다** (naver 기반 브랜드 전용 도구). `list_promotions`
1회 외에는 신규 MCP 호출 없이 다른 섹션 응답만 재사용한다:

- section-1의 `get_target_progress_v2` 응답 — 목표/소진율/ROAS. **브리즘은 revenue 목표
  미등록(target: 0)이 기본이라 목표 매출/목표 ROAS/매출 달성률이 N/A인 게 보통** — N/A인 목표
  수치를 근거로 삼은 문장은 쓰지 않고, 실적(소진액/기간 매출/실제 ROAS) 중심으로 쓴다.
  기간 매출/실제 ROAS는 항상 Airbridge 기준.
- section-3 공유 응답(6개월 monthly_table) — 월별 광고비/매출/ROAS 추이.
- section-4용으로 산출한 전체 매출 vs 광고 매출 추이 — 오거닉(전체−광고) vs 광고 비중 변화.
- section-5용으로 산출한 채널별 매출·ROAS 전월 대비 변화.

**우선적으로 찾을 특이사항 다섯 유형** (해당 사항이 있을 때만 — 억지로 채우지 않는다):

- **(a) 예산 재검토가 필요한 성장 신호** — 채널 매출/ROAS가 전월 대비 뚜렷하게 성장, 근거
  수치 필수. (예: "Google Ads 매출이 전월 대비 +22.4% 성장, ROAS도 240.3%p 개선되며 예산
  확대를 검토할 시점.")
- **(b) 원인 확인이 필요한 하락 신호** — 채널 매출·ROAS가 전월 대비 뚜렷하게 하락하거나 다른
  채널 대비 눈에 띄게 나쁨.
- **(c) 효율 변화가 뚜렷한 채널** — 고효율이지만 추세가 꺾이는 채널, 또는 눈에 띄게 개선된 채널.
- **(d) 오거닉 vs 광고 매출 비중 변화** — 6개월간 광고 매출 비중이 커지거나 작아지는 추세면
  구조적 변화로 기술.
- **(e) 프로모션/이벤트 영향 (이월 효과 포함)** — **프로모션명과 기간을 반드시 함께 언급**:
  - 기간이 MTD와 겹치면(할인/세일 등) 그 기간/직후 성과·매출 변화를 데이터로 확인해 서술.
  - 분석 기간 직전(30일 내) 종료면: 브랜딩/인지도형 → 이월 효과 가능성, 단기 할인형 → 종료 후
    반동(일시 하락) 가능성 관점. 성격이 불명확하면 "~일 가능성이 있다" 수준까지만.
  - 어느 경우든 변화가 뚜렷하지 않으면 그 사실을 그대로 쓴다 — 있었다고 지어내지 않는다.

**작성 원칙**:
- 각 불릿 = "수치(무슨 일) + 시사점(왜 신경 써야 하는지)". truism·단순 나열 금지.
- **3~5개로 제한** — 임원 보고이므로 "정말 중요한 것만" (빌더도 5개 초과분은 잘라낸다).
- 새로운 수치를 지어내지 않는다. 근거 없는 원인 추정 금지 — "확인/점검이 필요하다"까지만.

## 빌더 `s2.bullets[].color` 규칙

| color | 색 | 용도 |
|---|---|---|
| `green` | #16a34a | 성장/개선 신호. 프로모션 효과가 뚜렷이 긍정적인 경우 포함 |
| `red` | #dc2626 | 하락/점검 필요 신호. 프로모션 기간/직후 매출 하락 포함 |
| `neutral` | #78716c | 중립 관찰 — 비중 변화 안내, 효과 불분명한 프로모션, "가능성" 수준의 이월 효과 |
