# MTD Section 2: Executive Summary

**report_type:** `mtd-report` (항상 포함). 신규 MCP 호출 없음. **`assets/prepare.py` 출력의 `digest`**(와 `facts.pacing`)만
근거로 실행 모델이 직접 쓴다 — 응답 파일을 열어 보지 않는다. 근거 수치가 없는 문장(원인 추정, 변경 이력, 예측)은 쓰지 않는다.

**무엇을 어떻게 쓸지(목적·작성 규칙·문장 규칙·예시)는 `guides/weekly-summary.md`를 따른다.** 그 파일은 비개발자가
노션(TBWA: 요약 가이드 라이브러리 › Weekly Summary)에서 고치는 가이드의 사본이다 — 사람이 검증한 문구라 본문은 고치지
않고, 이 보고서에 맞춰 읽는 법(대응 관계)만 아래에 적는다. 이 문서는 대응 관계, 근거 데이터, 빌더 입력 형식만 정한다.

## 왜 Weekly 가이드인가

standard 플러그인에는 weekly 보고서가 없고 MTD가 그 자리다 — 월 중간 진행 점검이라 Weekly의 [소진](월 예산 소진율 +
기간 진행률)·[효율] 구조가 맞는다. 가이드의 섹션 이름 "Weekly Summary"는 이 보고서에서 두 번째 섹션
**"Executive Summary"**(s2) 자리에 들어간다.

## 대응 관계 — 가이드의 말을 이렇게 읽는다

| 가이드 | 이 보고서 | digest 키 |
|---|---|---|
| 이번주 | 당월 1일~기준일 | `기간.당월`, 값은 `당월` |
| 전주 | 전월 같은 기간(1일~기준일의 일, 전월 말일을 넘으면 말일까지) | `기간.전월 동기`, 값은 `전월 동기` |
| 전주 대비 변화 | 전월 동기 대비 변화 | `전월 동기 대비` |
| 월 예산 소진율 | 월 예산 대비 당월 누적 광고비 | `예산.소진율`(`예산.월예산`) |
| 기간 진행률 | 월 진행률(기준일의 일 ÷ 당월 일수) | `예산.월 진행률` (= `facts.pacing.month_progress_pct`) |

- 색 기준은 가이드 그대로 **전월 동기 대비 변화**에 쓴다: [소진] 광고비 -15% 이하 또는 +25% 이상 빨강, 그 밖에 ±10% 이상
  노랑, 나머지 회색 / [효율] CPV 10% 이상 상승 빨강, 10% 이상 하락 초록, 나머지 회색.
- 목표 예산이 없으면 `예산` 키가 없다 — 가이드대로 소진율·기간 진행률은 뺀다.

## 근거 (`digest`)

- `전체`: 당월·전월 동기 값과 변화. 지표는 광고비·노출·클릭(+조회수·CPV는 조회수 지표가 있을 때만, 매출·ROAS는 매출
  지표가 있을 때만)·CPM·CTR·CPC다. 효율 지표는 원자 합의 비율이다.
- `매체`: 매체마다 당월·전월 동기·변화, `광고비비중`, 매체 목표가 있으면 `월예산`·`소진율`.
- `매체-캠페인`, `매체-캠페인-광고그룹`, `매체-캠페인-광고그룹-광고`: 단위마다 **당월 광고비 상위 + 전월 동기 대비 광고비
  변동(절대액) 상위**를 합친 행(이름은 `매체 / 캠페인 / …`). 응답에 없는 차원의 단위는 빠진다. `… 생략`은 빠진 행 수다.
- 전월 동기 값이 `-`이고 변화가 `신규`면 전월 같은 기간에 없던 것(신규 집행), `중단`은 당월 집행이 없다는 뜻이다.
- 변화율은 digest 값을 그대로 쓴다(가이드대로 정수 %로 반올림해도 된다, % 지표는 %p). 직접 계산하지 않는다.

## 이 플러그인에서 달라지는 점

- **조회수·CPV가 없는 브랜드**(digest에 `CPV` 키가 없다): 가이드의 "CPV(없으면 CPM·CTR)"대로 전체 첫 문장은 CPM·CTR로,
  매체·캠페인 줄의 CPV 자리에는 CPC(매출이 있으면 ROAS도)를 쓴다. 효율 색 기준(10% 상승 빨강·10% 하락 초록)은 CPC 변화에 쓴다.
- 캠페인 분석은 6번째 섹션(`references/mtd-report-section-6-campaign-analysis.md`)이 따로 맡는다 — s2는 가이드 형식의
  요약만 쓴다.
- 저장 훅이 없는 호스트(`references/legacy-flow.md`)에서는 digest가 없다 — 받은 응답에서 같은 기준으로 골라 가이드대로 쓴다.

## 빌더 입력

```json
"s2": {"groups": [
  {"title": "소진",
   "lead": "7월 1~20일 광고비는 <strong>₩56,052,132</strong>로 전월 동기 대비 +7%이며, 월 예산의 58.4%를 소진했습니다(월 진행률 64.5%).",
   "media": [
     {"name": "BRS", "desc": "광고비 ₩10,550,582로 전월 동기 대비 <strong>+31%</strong> 늘었습니다.",
      "bullets": [{"unit": "캠페인", "label": "00_통합(BS)_MO", "text": "광고비 ₩9,240,111로 전월 동기 대비 +35%입니다.", "tone": "red"}]}]},
  {"title": "효율", "lead": "전체 CPM은 ₩11,442로 전월 동기 대비 +15.5%, CTR은 1.03%(+0.08%p)입니다.", "media": [...]}
]}
```

- `title`: `소진`·`효율`(화면에 `[소진]`처럼 대괄호를 붙인다). `lead`: 가이드의 첫 문장.
- `media[].name`: digest의 매체 이름 그대로(점 색은 빌더가 붙인다). `desc`: 매체마다 한두 문장.
- `bullets[]`: 가이드 v1.5의 "캠페인"·"광고그룹" 두 묶음 — `unit`에 `"캠페인"` 또는 `"광고그룹"`을 넣으면 빌더가 같은 `unit`이
  이어지는 줄을 작은 제목 하나 아래에 모은다. `label`은 단위 표기 없는 이름. 캠페인 차원이 없으면 bullets를 비우고 `desc`만 쓴다.
- `tone`: 라벨 색 — `red`(빨강), `yellow`(노랑), `green`(초록), `neutral`(회색). 가이드의 색 이름을 이 값으로 옮긴다.
- 본문은 `<strong>`만 허용, 다른 태그는 글자로 보인다.
- 예전 형식(`{"bullets": [{"text", "tone"}]}` 카드, `"executive_summary"` 문자열)도 받는다 — `groups`가 있으면 `groups`가 우선이다.
