# Daily Section 6: 매체·캠페인·광고그룹·광고 성과 (D-1 vs D-0, 계층 표)

**report_type:** `daily-report` (항상 포함). 매체 → 캠페인 → 광고그룹 → 광고를 ▶/▼로 펼치는
**계층 표** 하나로 **전날(D-1)과 기준일(D-0)**을 비교한다. 시작은 매체 단위로 접혀 있고, 각 행은
그 단위의 합계("전체")다. 값이 있는 지표 중 광고비·매출·ROAS·클릭·CTR·전환 6개를 먼저 보여주며(나머지는 '지표 선택'으로 켠다),
각 값 아래에 D-1 대비 증감(비율 지표는 `%p`)이 붙는다. 기본 정렬은 광고비 내림차순이고 헤더를
누르면 바뀐다. 광고비 기준 제외 규칙은 없다.

> ℹ️ 트리 생성(레벨 판별·기간 분리·조상 보장·정렬)·표 HTML/JS(펼치기·정렬·검색·지표 선택·
> 더 보기)는 전부 빌더(공용 킷 `build_tree`/`LHKit.treeTable`)가 한다 — 모델은 아래 호출의
> 응답을 **가공 없이 전부** 빌더 입력 `s6`에 넘기기만 한다(`generic-report-pattern.md` 8절).

## MCP 호출 — 레벨마다 따로 (저장 훅이 없는 호스트의 폴백 절차에서만 이 문서를 따른다)

저장 훅이 있는 호스트는 `prepare.py`가 계층 호출(광고 레벨 포함, 지표 전체)을 `missing`으로 알려 주고 빌더 입력도
만들어 준다 — 이 문서를 읽지 않는다. 아래는 훅이 없어 응답이 대화에 그대로 들어오는 경우다.

모든 호출: `start_date` = target_date-1일, `end_date` = target_date, `time_grain: "day"`,
**`metrics` = 역할 키 5개**(디스커버리로 정한 `metric_keys`의 cost·impression·click·revenue·conversion 값 중 있는 것, 이름 그대로).

| 레벨 | `group_by` | `filters` | 횟수 |
|---|---|---|---|
| 매체 | — | — | 0 — **section-3 응답(7일, `group_by:["media"]`)을 그대로 재사용** |
| 캠페인 | `["media", "campaign_name"]` | 생략 | 1 |
| 광고그룹 | `["media", "campaign_name", "ad_group_name"]` | 생략 | 1 (`over 50,000 rows`로 거절되면 `{"media": ["<매체>"]}`로 매체마다) |
| 광고 | — | — | **0 — 부르지 않는다**(지표를 줄여도 응답이 수십만 자다). 계층 표는 광고그룹까지 펼쳐진다 |

- 하위 레벨에 없는 ROAS·CTR·CPC 열은 빌더가 역할 합으로 채운다(서버 값과 같은 배율). 조회수·영상 지표처럼
  역할 밖의 지표는 캠페인 이하에서 비어 나온다.
- `filters.media` 값은 디스커버리 응답 문자열 **그대로**. Organic(`media: null`)은 매체 레벨(section-3 응답)에서만
  한 행으로 나온다(`has_organic`이고 매출 있음 모드일 때만 표시).
- 호출들은 의존성이 없으므로 section-3 호출과 **한 메시지에서 병렬 발사**한다.
- 매체에 따라 `ad_group_name`이 비어 있을 수 있다(`(미지정)`으로 표시, 오류 아님).

## 빌더 `s6` 입력

```json
"s6": {
  "json_files": ["<캠페인 스텁 경로>", "<광고그룹 매체1 경로>", "...", "<광고 매체N 경로>"],
  "json": ["<section-3 응답 원문 문자열>"]
}
```

- 스텁으로 온 응답은 `json_files`에, 원본으로 온 응답(보통 section-3 응답)은 `json`에 **문자열
  통째로** 넣는다. 둘을 섞어도 된다. **section-3 응답을 반드시 포함한다** — 빠지면 매체 행이
  값 없이(`—`) 나온다.
- 빌더가 봉투의 `group_by` 접두 길이로 레벨을, 행의 `date`로 D-1/D-0을 판별한다. 모델은 행을
  고르거나 합치거나 옮겨 적지 않는다.

> 🚫 **응답이 크다고 느껴져도 선택지는 둘뿐이다**: (1) 원본을 가공 없이 전부 빌더에 넘기거나
> (2) 정말 불가능하면 `s6`를 빌더 입력에서 빼서 "데이터 준비 중"으로 표시한다. 다른 섹션 값
> 재사용·근사치·추정 수치 대체는 그 숫자가 진짜 쿼리 결과라도 **전부 금지**다.
