# 매체별 성과 추이 (공용 규칙)

daily-summary·mtd-summary·monthly-summary·mtd-detailed의 "매체별 성과 추이" 섹션이 공유하는 규칙이다.
스킬별 섹션 파일은 **기간**과 **재사용할 응답**만 정하고 나머지는 이 파일을 따른다.

## 무엇을 보여주나

매체마다 선 하나인 라인 차트다. 모든 매체가 같은 축이라 규모와 흐름을 함께 비교한다.

- **지표 선택**: 선택지는 응답 봉투의 `metrics` **전체**다(ELT가 서빙하는 지표 — 고정 목록 없음).
  역할 지표(광고비→노출→클릭→전환→매출)가 앞, 나머지는 응답 순서. 기본 선택은 매출(매출 없음
  모드면 클릭) 키. 각 점은 그 grain으로 서버가 계산한 값 그대로다 — 비율 지표(ROAS/CTR 등)도
  합산·재계산하지 않는다.
- **범례**: 매체별 값과 비중(%)을 보여주고, 누르면 그 매체를 끄고 켠다(축이 보이는 매체에 맞춰
  다시 잡혀 작은 매체의 흐름이 확대된다). "전체 보기"는 되돌리기.
  - 범례 값: `total` 응답을 넘기면 **기간 전체 값**(서버 집계 — 비율 지표도 정확), 없으면 **마지막
    기간 값**(이번 달·기준일).
  - 비중(%): 합산이 확실한 역할 지표(광고비·노출·클릭·전환·매출)에만 붙인다.
- **Organic**: `has_organic`이고 매출 있음 모드일 때 회색 선 하나. 값이 있는 지표에서만 보인다.
- 광고 매체가 8개를 넘으면 광고비가 작은 매체들을 "그 외 매체 N개"로 합친다(차트 전용).
- 행이 없는 기간: 단위가 `%`인 지표는 비워 두고, 그 외 지표는 0.

렌더링·정렬·색 배정·지표 목록 구성은 전부 빌더(공용 킷 `media_trend_from_envelopes` +
`LHKit.trendChart`)가 한다.

## 빌더 `s4` 입력 — 응답을 그대로 넘긴다 (집계 없음)

```json
"s4": {
  "json": ["<차트 기간 응답 원문>"],          // 또는 "json_files": ["<캡처 스텁 경로>"]
  "total_json": ["<같은 기간 total 응답 원문>"], // 선택 — 또는 "total_json_files"
  "promotions": [...]                          // 프로모션 브래킷을 쓰는 스킬만
}
```

- 차트 기간 응답: `group_by: ["media"]`, `time_grain` day 또는 month, **`metrics` 생략**. 스킬마다
  이미 받는 공유 응답을 그대로 재사용한다(섹션 파일 참고).
- total 응답(선택): 같은 `start_date`~`end_date`, `time_grain: "total"`, `group_by: ["media"]`,
  `metrics` 생략. `day_offset`으로 월을 자르는 6개월 차트는 total 한 번으로 같은 범위를 만들 수
  없으므로 넘기지 않는다(범례 = 이번 달 값).
- 모델은 행을 합치거나 고르지 않는다. 기간 키(날짜·월)는 빌더가 `target_date`로 만든다.
