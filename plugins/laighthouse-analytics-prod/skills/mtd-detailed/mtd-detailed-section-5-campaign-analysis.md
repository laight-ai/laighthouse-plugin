# Breezm MTD Section 5: 캠페인 분석 (Campaign Analysis)

**report_type:** `mtd-detailed` — **브리즘(airbridge 기반) 전용** (항상 포함). 표로 보여주는
섹션 7과 달리 **서술형**으로 특이사항과 액션 아이템을 짚는다.

> ℹ️ HTML 렌더링(`\n\n` 블록 → 인트로 `<p>` + 캠페인별 `<h4>`+`<p>`, `⚠` 주황색)은 빌더가
> 한다 — 모델은 아래 규칙으로 텍스트만 작성해 빌더 입력 JSON의 `s5.campaign_analysis`에 넣는다.

---

## 텍스트 생성: AI가 직접 작성 (신규 MCP 호출 없음)

⚠️ **`df_dify` MCP 서버는 호출하지 않는다** (naver 기반 브랜드 전용 도구 — 브리즘은 안 씀).
전부 다른 섹션 응답을 재사용한다:

- section-7(Campaign별 성과)의 매체-캠페인별 합산 데이터(노출/클릭/CTR/광고비/매출/예약 완료/
  CPA/ROAS — `get_ad_performance` total 응답 행에서 온 값)를 그대로 쓴다.
- 이 섹션에서만 쓰는 파생 지표는 그 자리에서 계산: `CPC` = 광고비 ÷ 클릭(클릭 0이면 N/A),
  `평균단가`(객단가) = 매출 ÷ 예약 완료(0이면 N/A). "구매"는 section-7의 `예약 완료`를 가리킨다.
- section-4의 `list_promotions` 응답 — MTD 기간과 겹치거나 직전에 끝난 프로모션 확인용.

**작성 원칙 — 반드시 지킬 것**:

1. **광고비가 큰 캠페인을 우선 검토**하되 광고비 순 나열 금지 — 같은 매체 내 다른 캠페인 대비
   ROAS/CTR/CPC/구매/평균단가가 확연히 높거나 낮아 "특이사항"으로 부를 만한 것만 고른다.
   ⚠️ **매체를 가로질러 CTR/CPC를 직접 비교하지 않는다** — 지면·과금 구조가 달라 스케일이
   다르다(같은 매체 내에서만). ROAS·CPA·예약 완료는 매체 간 비교 가능.
2. 특이사항마다 **원인 가설과 해결 방향을 간결히** 덧붙인다. 해당 캠페인 기간과 겹치거나 직전에
   끝난 프로모션이 있으면 **프로모션명과 기간을 함께 언급**하며 연계 서술(효과가 뚜렷하지
   않으면 그 사실 그대로).
3. **truism 금지** — 모든 문장은 구체적 수치를 근거로. 강조 수치는 `<strong>` 사용 가능.
4. 캠페인은 **2~4개만** 심층 분석 (전체를 다 훑지 않는다). 특이사항이 없으면 억지로 채우지
   않는다.
5. 새로운 수치를 지어내지 않는다 — 근거 없는 원인 추정은 "확인이 필요하다" 수준까지만.

## 빌더 `s5.campaign_analysis` 형식

`\n\n`으로 구분된 블록 문자열 — 첫 블록은 인트로 문단(빌더가 `<p>`), 이후 블록은 첫 줄이
캠페인명+매체(빌더가 `<h4>`), 나머지 문장이 본문(`<p>`). 캠페인 소제목에는 매체명을 괄호로
항상 함께 표기한다 (예: `리타겟팅_구매고객 (Meta Ads)`) — 같은 이름이 다른 매체에 있을 수 있다.

```json
{ "campaign_analysis": "특이사항이 확인되는 2개를 선정했습니다.\n\n리타겟팅_구매고객 (Meta Ads)\n광고비 ₩9,800,000으로 Meta Ads 내 2번째로 크지만, 예약 완료가 0건으로..." }
```

- 데이터가 없으면 `s5` 자체를 넣지 않는다 → "데이터 준비 중" 카드.
