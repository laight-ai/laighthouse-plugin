# 대용량 MCP 응답 대응 (ChatGPT Skills 전용 — 전 스킬 공용)

Claude Code판 플러그인은 `get_ad_performance`의 고카디널리티 응답(campaign/ad_group/ad 차원
포함)을 PostToolUse 훅이 가로채 파일로 우회시킨다. **ChatGPT Skills에는 훅(lifecycle hook)
개념이 없다** — 도구 응답은 항상 전문 그대로 모델 컨텍스트에 들어온다. 따라서 이 스킬 세트는
"받은 뒤 우회"가 아니라 **"애초에 크게 받지 않는다"** 전략으로 동일한 문제를 해결한다.

## 원칙

> 🚫 훅이 없는 환경에서 응답이 크다고 느껴져도 선택지는 여전히 정확히 둘뿐이다: (1) 호출
> 조건을 좁혀 다시 받거나, (2) 정말 처리 불가능하면 그 섹션을 "데이터 준비 중"으로 표시한다.
> 이미 받은 응답의 일부만 보고 나머지를 요약·추정·생략하거나, 비슷한 값으로 대체하는 것은
> 여기서도 여전히 금지다 — 원본 무결성 원칙(각 SKILL.md의 「데이터 처리 원칙」)은 훅 유무와
> 무관하게 동일하게 적용된다.

## 사전 예방 규칙

1. **캠페인/광고그룹/광고 차원(`campaign_id`/`campaign_name`/`ad_group_id`/`ad_group_name`/
   `ad_id`/`ad_name`)이 `group_by`에 하나라도 들어가는 호출은 날짜 구간을 최대한 좁혀서
   보낸다.** 각 SKILL.md/섹션 파일에 명시된 구간(예: D-1~D0 이틀, 최근 7일)을 그대로 지키고,
   임의로 구간을 늘리지 않는다.
2. **매체별로 나눠 호출해야 하는 섹션(`filters:{"media":[...]}`)은 반드시 매체마다 별도
   호출로 유지한다** — 한 번에 전 매체를 고카디널리티로 묶어 받지 않는다(섹션 파일의 호출
   명세가 이미 이렇게 설계돼 있다. 임의로 통합 호출로 바꾸지 않는다).
3. 그래도 한 번의 응답이 비정상적으로 커서(체감상 처리가 버거우면) 다음 순서로 대응한다:
   - 같은 조건을 **날짜를 더 잘게 쪼개** 여러 번 호출해 나눠 받는다(예: 이틀 → 하루씩 2회).
   - 그래도 안 되면 `filters`로 더 좁혀서(예: 매체 하나씩) 나눠 받는다.
   - 그래도 처리 불가능하면 (1)/(2)를 시도했다는 사실과 함께 해당 섹션을 "데이터 준비 중"으로
     표시한다(빌더 입력에서 그 `s*` 키를 뺀다) — 절대 다른 값으로 대체하지 않는다.
4. asset 스크립트(`dxd_table_rows.py` 등)를 호출할 때는 **항상 `json`에 원본 JSON 봉투
   문자열을 그대로 넘긴다** — `json_files` 입력은 Claude Code 훅 전용 경로이며 이 환경에서는
   쓰지 않는다(스크립트가 두 입력을 다 받더라도 여기서는 `json`만 쓴다).

## 각 SKILL.md/섹션 파일을 읽을 때

본문 중 "캡처 훅 스텁으로 오면 `json_files`에, 원본이면 `json`에" 식의 분기 서술은 Claude
Code 훅 환경 기준이다. **이 환경(ChatGPT)에서는 항상 "원본이 그대로 오는" 경로만 해당한다** —
`json_files` 분기는 무시하고 `json`에 원본 문자열을 그대로 넘기는 쪽으로만 진행한다.
